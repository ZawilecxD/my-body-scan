# 11x-mvp-build

Load `factory-delegation` from sibling `11x-references`. The calling agent remains coordinator: delegate bounded stage work to fresh workers when supported and authorized, accept their artifact evidence, and retain user decisions/checkpoints. Use recorded inline fallback otherwise. Follow this reference for ownership, context handoff and recovery; workers never recursively invoke the whole Factory.


Load references `product-factory-policy`, `mvp-status`, `unattended-policy`, `change-md`, `progress-format`, `handoff`, and `ui-refinement` from sibling `11x-references`. Execute sibling contracts through the coordinator and bounded workers, not nested slash commands. Factory policy adds product-level gates; unattended policy still governs each single slice.

## Guard

- Require foundation PRD, confirmed stack, architecture, roadmap, build summary (plus approved `ux-plan.md` for version-2 new builds; follow the explicit legacy exception) and current explicit stack/build approval evidence. Validate approved artifact revisions. Missing, stale or revoked approval: return to the relevant `11x-mvp` gate; no product-code writes.
- Preserve `context/`, project instructions and unrelated work. Never modify archive contents. Build approval covers ordinary implementation decisions, not unlimited external actions.
- Use one dedicated Factory integration branch for the approved roadmap, recorded in `mvp-status.md`. Do not merge to the default branch or archive changes automatically. Several slices are orchestrated here, never passed as one ticket to `11x-deliver`.

## Steps

1. **Reconcile.** Read the checkpoint, foundation documents, existing slice changes/plans/reviews, branch commits and handoffs. Reuse recorded change IDs and branch. Verify missing or contradictory evidence before trusting a completed checkpoint; inspect dirty work before repeating a partially executed phase. Select the first incomplete stage, then first dependency-ready incomplete slice. For version 2, resume UI stages using `ui-refinement`; preserve baseline evidence and approved designs. Do not rebuild completed functional slices to resume visual work.
2. **Bootstrap once.** If no successful bootstrap evidence exists, execute `11x-bootstrapper` using the exact command included in build approval. If files already exist after an interrupted bootstrap, inspect and repair only incomplete work; never rerun a destructive starter. Establish the approved test tooling here, run smoke checks, then execute `11x-standards-discover` and `11x-domain-discover` for missing knowledge artifacts. Checkpoint evidence. Do not silently introduce a different testing stack inside unattended slices.
3. **Start one slice.** Execute `11x-new --change <recorded-id> <slice-intent>` if its change does not exist. Honor uniqueness across changes, efforts and archive. Reuse an existing ID only when its identity matches this slice; otherwise record a new unique ID. Set `mode: unattended` and `source: product-factory` in the new change. Write `frame.md` with slice acceptance criteria, constraints and links to the approved PRD, stack, architecture and roadmap. Read these foundation artifacts and `ux-plan.md` when present as settled context when planning. Build shared UI components, semantic styling tokens and separated presentation/domain logic. Meet responsive/accessibility requirements now; defer full visual alternatives until functional QA passes.
4. **Plan and review.** Execute `11x-plan`, then `11x-plan-review`. Apply Critical findings through `11x-review-triage` once and re-review. Persist attempts across resumes; unresolved Critical findings block the slice. Require runnable automated criteria from the bootstrapped project.
5. **Implement phases.** Execute `11x-implement` or `11x-tdd` one phase at a time, with phase commits, until Automated Progress is complete. Choose the first unchecked **Automated** item; pending Manual items do not cause an infinite resume loop. Copy Manual items to the handoff without checking them. On failing automated checks, allow one focused repair pass; persist it, then block if still red.
6. **Review the slice.** Execute `11x-impl-review`, Critical triage once if needed, and re-review. Require automated evidence and no unresolved Critical findings before recording the slice as verified. Keep Manual checks and deferred suggestions visible. Leave the change at `impl_reviewed`; `mr_ready` applies only once an actual PR handoff is available. Do not write roadmap `## Done` or mark the change archived.
7. **Continue.** Checkpoint links and commit evidence after each slice and advance on the same integration branch. This allows dependent slices to use previous code without requiring a human merge between slices. Do not reset the repair budget for the same failing criterion on session restart, worker replacement or another failed fix. After the permitted repair/recheck fails, record blocked; a later externally resolved blocker or user-authorized revised scope may justify a new bounded attempt, with the reason preserved in History.
8. **Functional QA.** For version 2 with a planned UI pass, execute `11x-qa functional` against the assembled MVP and retain `functional-qa-report.md`. Otherwise use normal `11x-qa`. For blocking in-scope findings, repair in the owning change with appropriate tests and review, then rerun affected QA once. New cross-slice bugs may use a recorded defect change within approved scope. Persist attempts; unresolved failures block readiness. Out-of-scope requests return to product refinement rather than expanding the build silently.
9. **Post-MVP UI refinement (version 2).** Record `functional_ready` and its evidence, then execute `11x-ui-refine` in-process when the UI pass is planned/in progress. It owns candidate generation, the one interactive direction choice, rollout changes, visual review and final QA. A pending choice sets `awaiting_ui_approval` and returns to the user; missing tools block only this stage. Continue automatically when an existing choice is valid. Completed UI evidence skips re-generation. `not_applicable` skips the UI pass; explicit `deferred` delivers functional `handoff_ready` with remaining UI work. Version-1 runs follow legacy policy without a new gate.
10. **Final verification.** After UI changes require passing `design-review.md` and final `qa-report.md` for the resulting code. Reuse evidence returned by `11x-ui-refine` when current; do not repeat tests solely because the orchestrator resumed. Baseline QA cannot certify a changed frontend.
11. **Staging / handoff.** Use the project's deployment skill or tools only for the environment and actions covered by approval. Verify the final deployed revision (redeploy if the existing preview only contains the baseline) and a smoke journey before recording a URL as working. If deployment is unavailable or unauthorized, write exact setup steps and remain `handoff_ready`, not `ready`. Production and new paid resources require their own authorization. Open or update one aggregate PR through the project's git skill/MCP if authorized; query for an existing branch PR before creating one. If unavailable, leave a paste-ready body in `mvp-handoff.md`. Include functional and final QA, UI direction/coverage/review/deferred work, commit/revision, slice and rollout-change evidence, pending Manual checks, assumptions, costs and deployment status. Include refinement changes in the aggregate PR; for an explicitly adopted legacy merged run, use its recorded new refinement branch/PR. No auto-merge or auto-archive.

## Done when

After an aggregate PR is actually created or found, record its URL in the Factory handoff and each included change, and set those reviewed changes to `mr_ready`. Without a PR, preserve `impl_reviewed` and report the paste-ready handoff honestly.

`mvp-status.md` and `mvp-handoff.md` accurately show `ready`, `handoff_ready`, `awaiting_ui_approval`, `blocked`, or a user-requested `paused`. Functional readiness alone is not completion of a planned UI pass. Use the readiness rules from `mvp-status`; completion of automated slice tasks alone is insufficient. Print verified URLs and actionable remaining work.
